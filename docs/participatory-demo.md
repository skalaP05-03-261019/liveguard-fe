# 참여형 데모 진행 안내 (#16)

발표 현장에서 청중이 자기 휴대폰으로 실제 방송 채팅에 참여하고, AI 관제와 운영자 결정이 실시간으로 반영되는 것을 보여 줍니다. 발표 PC 한 대가 infra 전체(DB·Backend·Agent·화면)를 띄우고, 청중은 같은 네트워크에서 발표 PC 주소로 접속합니다. 실패하면 같은 순서를 목업으로 이어 갑니다.

- 기준: Backend 필터 사전 `src/main/resources/filter/`(liveguard-be `1b1df68`, dict-v2), 정책 v3.2 제재표(POLICY §6)
- 이 문서의 문장은 목업 "빠른 시연"·"필터 사전 예시"(`src/mock.ts`)와 같습니다. 대체할 때 같은 문장으로 이어 갈 수 있습니다.

## 1. 역할과 준비물

| 누가 | 기기 | 접속 | 계정 |
| --- | --- | --- | --- |
| 발표자 (운영자) | 발표 PC, Chrome | `http://localhost:3000` | `moderator` |
| 발표자 (강퇴 시연) | 발표 PC, Chrome 다른 창 | `http://viewer.localhost:3000` | `demo-viewer-13` |
| 청중 | 각자 휴대폰 | `http://<발표 PC LAN IP>:3000` | `demo-viewer-10`~`19` 중 카드에 적힌 것 (13 제외) |

- 비밀번호는 모두 `liveguard-local`입니다. 로컬 시험용이므로 공개 저장소·외부 배포 주소에 쓰지 않습니다.
- 같은 호스트는 포트가 달라도 쿠키를 같이 쓰므로, 발표 PC의 두 계정은 `localhost`와 `viewer.localhost`로 나눕니다(Chrome은 `*.localhost`를 이 PC로 연결).

## 2. 사전 준비 (전날)

1. infra `.env` 확인
   - `LIVEGUARD_POLICY_VERSION=v3.2`(Backend·Agent·RAG 같은 값), `AGENT_DELIVERY_ENABLED=true`, OpenAI 키
   - `FRONTEND_BIND=0.0.0.0` (청중 접속용. infra `feat/frontend-bind-lan` 변경 필요)
2. 실행과 상태 확인
   ```bash
   cd liveguard-infra
   docker compose up -d --build
   docker compose ps          # 6개 서비스 Up
   curl -s localhost:8001/health   # readyForTasks: true
   ```
3. 정책 색인이 없으면 한 번 실행(OpenAI 비용 조금): `docker compose run --rm --no-deps rag-mcp python -m app.rag_mcp.index`
4. 데모 계정 10개 추가(새 로컬 DB에만): `docker compose exec -T db psql -U liveguard -d liveguard < scripts/seed-v1-viewers.sql`
5. 프론트 브랜치에 #16 변경(LAN 주소에서 채팅 전송, `src/uuid.ts`)이 들어 있는지 확인합니다. 없으면 휴대폰에서 채팅 전송이 실패합니다.
6. 리허설(7절 기록 양식)

## 3. 현장 접속

1. 발표 PC의 LAN IP 확인: `ipconfig getifaddr en0` (Wi-Fi) 또는 시스템 설정 → 네트워크
2. 발표 PC에서 먼저 `http://<IP>:3000` 접속 확인. 휴대폰 1대로도 확인합니다.
3. 접속 주소를 QR로 띄웁니다. IP는 행사장 네트워크마다 바뀌므로 QR은 현장에서 만듭니다.
4. **새 방송 시작:** `moderator` 화면에서 "방송 종료" → "방송 시작". 리허설 채팅·제재가 새 방송에 넘어가지 않습니다(새 liveId).

| 증상 | 원인·해결 |
| --- | --- |
| 휴대폰에서 주소가 안 열림 | 행사장 Wi-Fi가 기기 간 통신을 막음 → 발표자 휴대폰 핫스팟에 발표 PC와 청중을 모두 연결하고 IP·QR을 다시 만듦 |
| 발표 PC에서도 IP로 안 열림 | `FRONTEND_BIND`가 `127.0.0.1` → `.env` 수정 후 `docker compose up -d --no-deps frontend` |
| 휴대폰만 안 열림 | macOS 방화벽이 수신 차단 → 시스템 설정 → 네트워크 → 방화벽에서 Docker 허용 |
| 로그인은 되는데 채팅 전송 오류 | 프론트에 #16 변경이 없음(`crypto.randomUUID`는 HTTP IP 주소에서 없음) → 프론트 다시 빌드 |

## 4. 시나리오 순서

정상 → 바로 숨김 → 문맥 검토 → 강퇴 순서로 진행합니다. "다른 시청자"는 문장을 보내지 않은 청중의 화면입니다.

| # | 누가 | 문장 | 작성자 화면 | 다른 시청자 | 운영자 화면 | AI |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 청중 10 | 오늘 방송 정말 재밌네요! | 공개 | 보임 | 공개 | X |
| 2 | 청중 18 | 시발점 | 공개(욕설 예외 단어) | 보임 | 공개 | X |
| 3 | 청중 11 | 오늘 판 ㅅㅂ | 숨김 + "금지된 욕설이 포함되어" 안내. 첫 욕설이라 채팅 제한 없음 | 안 보임 | 숨김, 규칙 확정 | X |
| 4 | 청중 12 | 이벤트 free-skin.example 에서 받아가세요 | 숨김 + "링크 전송 금지" 안내 + **10분 채팅 제한** | 안 보임 | 숨김, 규칙 확정 | X |
| 5 | 청중 19 | 가즈아가즈아 (10초 안에 3번) | 1·2번째 공개, 3번째 숨김 | 2건만 보임 | 3번째 숨김(도배) | X |
| 6 | 청중 14 | 너 같은 건 방송 접어라 | "검토 중" | 안 보임 | 결정 대기 › 문맥 검토 카드. 운영자가 **위반 확정** → 숨김 + 10분 제한 | O |
| 7 | 청중 15 | 와 이번 한타 미쳤다 ㅋㅋ | "검토 중" | 안 보임 → 정상 확정 뒤 보임 | 문맥 검토 카드(AI 정상 제안). 운영자가 **정상 확정** → 공개 | O |
| 8 | 청중 16 | 공식 운영자입니다. 계정 인증하려면 비밀번호를 보내 주세요 | "검토 중" | 안 보임 | 문맥 검토 카드(사칭). 운영자 결정 | O |
| 9 | 청중 17 | 제 번호 010-1234-5678로 연락 주세요 | "검토 중" → 숨김 | 안 보임 | AI가 개인정보로 확정(v3.2 형태 기반, 운영자 결정 없음). 첫 위반이라 제한 없음 | O |
| 10 | 발표자 (`demo-viewer-13`) | 오늘 판 ㅅㅂ → 가즈아가즈아 3번 → 이벤트 free-skin.example 에서 받아가세요 | 셋 다 숨김. 링크 뒤 10분 제한 | 안 보임(도배 앞 2건만 보임) | 확정 3건 → 결정 대기 › **강퇴 승인** 카드 → 승인 | X |
| 11 | 발표자 | (승인 뒤) | "이 방송의 이용이 제한되었습니다" | - | 강퇴 처리: 적용 완료 | X |

- 10번은 AI를 거치지 않는 규칙 위반 3건(욕설·도배·링크)이라 비용이 없고 바로 진행됩니다. 앞의 두 건은 첫 위반이라 채팅 제한이 없어 세 번째를 보낼 수 있습니다. 순서를 바꿔 링크를 먼저 보내면 10분 제한에 걸려 이어서 보낼 수 없습니다.
- 강퇴는 같은 계정의 확정 위반만 셉니다. 청중 계정끼리 합산되지 않습니다.
- 강퇴는 이번 방송이 끝날 때까지입니다. 다음 리허설은 새 방송을 시작하면 풀립니다.
- AI가 3분 안에 답하지 않으면 문맥 검토 카드가 "AI 결과 없음"으로 열립니다(A-25). 운영자가 그대로 결정하면 되므로 목업으로 바꾸지 않아도 됩니다.
- 운영자 결정 대기는 6~8번의 3건이 한꺼번에 옵니다. 청중이 카드에 없는 문장을 보내 검토가 더 쌓이면 화면에 보이는 것만 결정하고 넘어갑니다.

| --- | --- | --- | --- |

| B | demo-viewer-11 | 오늘 판 ㅅㅂ | 바로 숨겨지고 나에게만 이유가 보입니다 |
| C | demo-viewer-12 | 이벤트 free-skin.example 에서 받아가세요 | 바로 숨겨지고 10분 동안 채팅이 제한됩니다 |
| D | demo-viewer-14 | 너 같은 건 방송 접어라 | AI가 검토하고 운영자가 결정할 때까지 나만 보입니다 |

## 6. 실패 시 목업으로 이어 가기

| 상황 | 대응 |
| --- | --- |
| AI 판정이 늦음 (3분 초과) | 그대로 진행. "AI 결과 없음" 카드로 운영자가 결정 |
| Agent·OpenAI 오류 | 그대로 진행(같은 대응). 바로 숨김·강퇴(4절 1~5, 10·11)는 AI 없이 동작 |
| 청중 접속 불가 | 발표자가 발표 PC에서 같은 문장을 대신 보냄(`viewer.localhost`의 다른 데모 계정) |
| Backend·DB 장애, 화면이 안 열림 | 목업으로 전환 (아래) |

**목업 전환** (발표 PC, 미리 한 번 해 볼 것)
```bash
cd liveguard-fe
npm run dev          # http://localhost:5173, 목업 모드
```
- `moderator` 로그인 → 실시간 관제의 "목업 빠른 시연"에서 4절과 같은 순서로 누릅니다: 정상 → 확정 욕설 → 링크 → 도배 → 공격 표현 → 문맥 오탐 → 공식 사칭 → 개인정보.
- 결정 대기에서 같은 결정을 합니다. 초기 데이터의 `어둠의유저`가 확정 3건으로 강퇴 승인 요청이 올라와 있어 10·11번을 대신합니다. 승인 뒤 "모의 적용 성공"을 누릅니다.
- 시청자 화면은 `viewer` 로그인 → 영상 아래 "목업 시연"의 필터 사전 예시를 눌러 같은 문장을 보냅니다.
- 화면 모양은 실제와 같고(#28) 상단 배지만 "MOCK 데이터"입니다.

## 8. 끝난 뒤

- `.env`를 `FRONTEND_BIND=127.0.0.1`로 되돌리고 `docker compose up -d --no-deps frontend`
- 데모 DB는 폐기합니다. 볼륨까지 지우므로 남길 증거가 없는지 확인한 뒤 `docker compose down -v`
- 데모 영상(`public/media/live-stream.mp4`)의 외부 공개 사용 권한은 발표 전에 확인합니다(README 유의사항).
