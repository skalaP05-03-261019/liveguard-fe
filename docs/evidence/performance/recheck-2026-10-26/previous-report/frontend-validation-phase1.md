## 2. 핵심 프론트엔드 성능 지표와 현재 검증 상태

아래 **목표는 평가 기준 후보**이며, `phase1` 대비 개선 결과가 아니다. 100ms·100건/초는 LIVE:GUARD의 잠정 시험 목표다. INP·LCP는 일반 웹 성능 권장 기준이지만 이 프로젝트의 현장 측정치는 아직 없다. [상세 정의와 타당성 검토](../liveguard-fe/docs/frontend-performance-test-plan.md#2-평가-항목-타당성-검토)

| 지표 | 측정 시작 → 끝 / 조건 | 초기 목표 | 이번 검증 결과 | 상태 |
| --- | --- | --- | --- | --- |
| 채팅 표시 지연 | 허용된 메시지의 SSE 수신 → 다음 화면 페인트 | P95 ≤100ms | **미측정**. 합성 주입→DOM 추가 P95 7.4ms(10건/s), 2.8ms(100건/s)는 다른 구간 | 미검증 |
| 실시간 이벤트 반영 지연 | 상태 SSE 수신 → 해당 채팅의 화면 상태 변경. API 재조회 시간을 별도 기록 | P95 ≤100ms 잠정, 네트워크 조건 명시 | **미측정**. 합성 200행 상태 변경은 다음 프레임 4.1ms | 미검증 |
| 채팅 처리량 | 서버 저장·전달·클라이언트 최신 창을 각각 대조 | 100건/s × 5분; 허용 범위 ID 누락 0 | 합성 100건/s × 10초에서 DOM 1,000/1,000, 최신 200행 유지 | 부분 측정 |
| 화면 부드러움 | 부하 중 프레임 간격·50ms 초과 작업·입력 지연 | 60Hz에서 약 16.7ms 프레임 지향. 단독 합격 기준 아님 | 합성 10초 프레임 간격 P95 16.7ms, 장기 작업 0건 | 부분 측정 |
| 사용자 입력 응답성 | 실제 클릭/입력 → 다음 페인트(INP); 승인 서버 완료와 분리 | 현장 페이지 조회 P75 ≤200ms | INP·강퇴 50건 연속 조작 미측정 | 미검증 |
| 메모리 안정성 | 60분 방송, 15분 간격 GC 후 heap·DOM·조작 지연 | 1시간 후 안정 구간 확인 | 20초 합성 시험 전후 heap만 기록, 누수 판정 불가 | 미검증 |
| 메시지 정합성 | 서버 저장 ID·버전 대비 허용된 최신 80/200건, 재연결 후 순서 | 누락·중복·순서 오류 0건 | 합성 DOM 미관찰 0건; 실제 SSE·재연결 미측정 | 부분 측정 |
| 초기 로딩(LCP) | 첫 탐색의 최대 콘텐츠 표시. 로그인 후 SPA 전환은 별도 측정 | 현장 페이지 조회 P75 ≤2.5초 | LCP 미측정 | 미검증 |

**LIVE:GUARD 우선 검증 4가지:** (1) 100건/s에서 최신 채팅 창의 렌더링·정합성, (2) AI 판정의 서버 처리 시간과 FE 상태 반영 시간 분리, (3) 강퇴 승인 클릭 피드백과 실제 제재 완료 시간 분리, (4) 60분 방송과 SSE 재연결 후 메모리·정합성 유지. 목표와 판정법은 [FE 테스트계획서](../liveguard-fe/docs/frontend-performance-test-plan.md)에, 원자료 해석은 [결과서](../liveguard-fe/docs/frontend-performance-test-results.md)에 기록했다.

## 6. 성능 측정 원자료와 타당성

한 번의 macOS 14.0 / Node 24.20.0 / Chromium 156.0.8078.4 / 1440×900 / 생산 빌드 미리보기 / 목업 반응형 피드 측정이다. 측정 코드와 원자료는 FE `docs/frontend-performance-test-plan.md`, `docs/frontend-performance-test-results.md`, `docs/evidence/performance/frontend-smoke.json`에 있다. FE HEAD `c75e0bf`에 당시 미커밋 UI 변경이 포함됐다. **PR #61 머지 후 결과가 아니며 Phase 1 동일 조건 결과도 없다.**

| 구간 | 주입·관찰 | DOM 추가 지연 P95 | 프레임 간격 P95 | 50ms 초과 작업 | GC 후 heap |
| --- | ---: | ---: | ---: | ---: | ---: |
| 10건/초 × 10초 | 100 / 100 | 7.4ms | 16.7ms | 0건 | 3.61→4.34MiB |
| 100건/초 × 10초 | 1,000 / 1,000 | 2.8ms | 16.7ms | 0건 | 4.33→5.32MiB |
| 200건 상태 변경 | 200 / 200 | 다음 프레임 4.1ms | — | — | — |

이 값의 시작점은 **목업 데이터 주입**, 끝점은 **DOM 추가**다. SSE 수신→실제 화면 페인트 P95 100ms 목표, 실제 100명/100채팅·초 처리, 5분 지속, 60분 메모리 안정, LCP·INP·CLS는 이 결과로 판정할 수 없다. 100건/초가 10건/초보다 빠른 값은 단 한 번의 타이머·Vue 갱신 배치 영향일 수 있어 성능 향상으로 해석하지 않는다.
