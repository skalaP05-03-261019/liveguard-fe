# 관제 대시보드 UI·성능 개선 보고서 (#43–#46)

## 배경과 목적

기존 시스템 운영자 화면은 채팅 판정 분포, 강퇴 승인 요청 표, 방송별 현황, AI 내역을 순서대로 보여줬다. 전체 상태를 보고하는 데는 적합했지만, 운영자가 지금 확인해야 할 요청을 찾으려면 여러 영역을 살펴야 했다. 정상 비율이 약 98%인 예시에서는 큰 파란 막대가 가장 먼저 보였고, 비정상·판정 대기 수치는 정상과 같은 강조 수준이었다.

별도로 실제 API 화면을 확인하면서, 채팅·관제 SSE 이벤트마다 메시지·검토·사건 전체를 재조회하는 구조를 발견했다. 이 부분은 **스트리머·시청자 API 연결을 담당하는 `LiveConsole.vue`**의 변경이다. 시스템 운영자 집계 API를 새로 구현한 작업은 아니다.

이번 변경은 아래 네 이슈에 대응한다. 기존 기간 통계 PR #42는 main에 머지된 상태이며, 이번 브랜치에도 최신 main을 합쳤다.

| 이슈 | 문제 | 변경 후 사용자가 얻는 것 |
| --- | --- | --- |
| #43 | 연속 이벤트마다 중복 HTTP 조회 | 요청을 모아 처리하면서 최신 채팅과 상태를 표시 |
| #44 | 대기·실패를 여러 표에서 찾아야 함 | 첫 화면 요약에서 관련 요청 목록으로 바로 이동 |
| #45 | 모바일 설명 반복과 넓은 표 | 요약 정보를 먼저 읽고 필요한 행만 펼쳐 상세 확인 |
| #46 | 비율의 표본 규모와 자동 눈금 변화가 덜 드러남 | 검사 건수와 눈금을 보고 비율·길이를 해석 |

## 1. 실시간 조회: 무엇을 왜 어떻게 바꿨는가

### 변경 전

`LiveConsole.vue`의 이벤트 핸들러가 `refresh()`를 호출했다. 운영자 기준 refresh 한 번에 세션 확인 1회, 메시지 1회, 문맥 검토 1회, 강퇴 검토 1회, 사건 1회로 기본 5개 요청이 발생했다. `TOOL_START`와 `TOOL_END`도 같은 목록 조회를 수행했다.

이전 응답을 무시하는 순번 검사는 있었지만, 이미 시작한 요청 수를 줄여 주지는 않았다. 연속 이벤트가 오면 사용하지 않을 응답까지 서버와 브라우저가 처리해야 했다.

### 변경 후

- 이벤트는 80ms 동안 모아 조회한다. 80ms는 짧은 연속 이벤트를 합치기 위한 대기 시간이며 실측으로 도출한 최적값은 아니다.
- 진행 중 조회는 하나만 유지한다. 그동안 추가된 갱신 요구는 메시지·관제 플래그로 합쳐 현재 조회가 끝나면 후속 조회한다. 이벤트 하나마다 후속 요청을 따로 예약하지 않는다.
- `CHAT`은 세션 확인과 메시지 조회만 수행한다. 검토·사건은 채팅 이벤트 때문에 다시 읽지 않는다.
- `TOOL_START`·`TOOL_END`는 받은 이벤트를 로그에 기록하고 목록 API를 호출하지 않는다.
- 그 밖의 상태 변경 이벤트는 기존과 같이 필요한 전체 상태를 확인한다.

```text
변경 전: 이벤트마다 세션 → 메시지 + 문맥 검토 + 강퇴 검토 + 사건
변경 후: 이벤트 묶음 → 진행 중 조회 확인 → 필요한 목록만 조회
                               └ 진행 중이면 다음 조회에 요구를 합침
```

숨김 메시지의 즉시 제거는 80ms 묶음 처리를 기다리지 않는다. 세션·방송 변경 시 오래된 응답을 무시하는 검사, 강퇴·방송 종료 처리, 주기적인 5초 복구 조회도 유지한다. 사용자 변경을 감지한 후 재로딩을 기다리는 경로는 조회 큐와 서로 기다리지 않도록 조정했다. 이미 전송한 HTTP 요청을 취소하는 방식은 아니다.

### 요청 수 비교와 해석

같은 브라우저 테스트 fixture에서 채팅 이벤트 20개를 보낸 후 첫 메시지 조회가 시작되면 20개를 추가했다. 메시지 응답에는 180ms 지연을 넣었다. 이어 `TOOL_START`·`TOOL_END` 각각 20개를 보냈다. 변경 전 기준은 구현 시작 시점 커밋 `fd7ba65`의 `LiveConsole.vue`이며 임시 복사본에서 실행했다.

| 관측한 요청 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 채팅 구간 메시지 조회 | 41 | 2 |
| 채팅 구간 검토 조회 | 82 | 0 |
| 채팅 구간 사건 조회 | 41 | 0 |
| 채팅 구간 세션 조회 | 42 | 2 |
| 채팅 구간 현재 방송 조회 | 1 | 0 |
| 도구 이벤트 구간 추가 API 요청 | 200 | 0 |

변경 전 실행이 더 오래 걸려 채팅 구간에 5초 주기 조회도 포함됐다. 따라서 두 열은 동일한 시간 길이의 부하 측정이 아니며, 이 수치를 사용자 응답 속도의 개선율로 환산하면 안 된다. 운영 환경 처리량, FPS, p95 지연 시간을 측정한 결과도 아니다. 자동 회귀 테스트는 최신 메시지가 최종 표시되는지와 메시지 조회 최대 2회, 채팅에 따른 검토·사건 조회 0회, 도구 이벤트 추가 조회 0회를 검사한다.

## 2. 위험 정보: 분포를 읽기 전에 확인할 일부터 찾게 변경

상단에 강퇴 결정 대기, 최장 대기, **확인된 강퇴 실행 실패** 세 카드를 추가했다. 선택한 방송 필터에 해당하는 데이터로 계산한다.

| 조작 | 결과 | 이유 |
| --- | --- | --- |
| 강퇴 결정 대기 클릭 | 강퇴 요청 표로 이동, 대기 상태 필터 적용 | 숫자를 확인한 뒤 요청을 다시 찾는 동선을 줄임 |
| 최장 대기 클릭 | 같은 대기 요청 목록으로 이동 | 오래 기다린 요청이 있음을 드러냄 |
| 실행 실패 클릭 | 확인된 실패만 표시, 필터 안내와 해제 버튼 제공 | 승인과 실제 실행 결과를 구분해 확인 |

목록 이동 시 표 영역으로 키보드 초점도 옮긴다. 결과 미확인은 확인된 실패 집계에 포함하지 않는다. API 미연동 모드에서는 세 카드에 0건 대신 `—`·`연동 API 없음`을 표시하고 클릭을 비활성화한다.

채팅 판정 범례는 비정상·판정 대기 수치를 먼저 보이도록 배치하고 정상 수치의 강조를 낮췄다. 분포 막대의 정상·비정상·대기 색과 모수는 바꾸지 않았다. 기간 통계에도 같은 공용 범례 스타일이 적용된다.

## 3. 모바일: 핵심 열을 먼저 표시하고 나머지는 상세로 제공

기간 통계의 긴 도입 문장을 줄이고, 채팅 판정 정의는 `판정 기준` 도움말을 펼쳐 확인하도록 했다. 데이터 자체를 없애지 않고 설명과 상세 정보의 노출 순서를 바꿨다.

| 모바일 표 | 먼저 보여 주는 열 | 펼쳐 볼 수 있는 정보 |
| --- | --- | --- |
| 강퇴 요청 | 시간·스트리머 결정·실행 상태 | 방송·사용자·사유·기준 사건·대기/결정 소요 시간 |
| 실시간 방송별 현황 | 방송·숨김률·강퇴 대기 | 스트리머·시청자 수·검사/숨김/판정 대기·강퇴 요청과 결정 수치 |
| AI 내역 | 시간·사용자·확정 상태 | 방송·메시지 원문·유형·조치 |
| 기간 방송 목록 | 방송·시작·상태 | 검사/비정상/판정 대기·강퇴 승인/기각/대기 수치 |

상세는 기본 HTML `details/summary`를 사용해 터치와 키보드로 연다. 긴 문자열은 상세 영역에서 줄바꿈한다. 데스크톱은 기존 상세 열을 계속 보여 준다. 360px·390px에서 문서 전체의 가로 넘침과 상세 열기를 검사했다.

## 4. 차트: 길이와 비율을 해석할 단서를 추가

방송별 비율 막대에는 0·중간·최댓값 눈금을 추가하고, 각 방송의 검사 건수를 비율 옆에 표시했다. 작은 표본의 높은 비율과 큰 표본의 낮은 비율을 구분하는 데 필요한 정보다. 선 그래프에는 `세로축 자동 눈금`과 기간에 따라 달라진다는 안내를 붙였다.

자동 눈금은 계속 사용한다. 한 화면 안 방송들은 같은 눈금으로 비교하지만, 기간을 전환하면 눈금이 달라질 수 있다. 서로 다른 기간의 차트를 길이만으로 직접 비교하지 않도록 값과 눈금을 함께 제공하는 선택이다. 고정 눈금 전환 기능은 이번에 추가하지 않았다.

날짜별 표 보기, 방송이 없던 날 선 끊김, 키보드 방향키 툴팁, 라벨·건수·비율 표시는 유지한다.

## 6. 검증과 재현

```bash
VITE_USE_API=true npm run build
VITE_USE_API=false npm run build
npm run test:chat
CHAT_EVIDENCE_DIR=docs/evidence/dashboard-review node --test --test-name-pattern='admin attention' tests/live-chat.test.cjs
```

- Mock/API 모드 각각 타입 검사와 프로덕션 빌드를 확인한다.
- 전체 테스트는 기존 56개와 새 2개로 구성된다. 새 테스트는 연속 이벤트 요청 수와 최신 메시지 반영, 위험 요약 필터, 초점 이동, API 빈 상태, 모바일 상세, 360·390px 가로 넘침, 눈금·검사 건수, 키보드 툴팁을 확인한다.
- 앞선 전체 실행에서 기존 목업 초기 로그인 버튼 대기 타임아웃이 1회 있었다. 이후 표준 전체 실행은 58개 통과했고 최종 화면 저장은 관리자 UI 테스트를 분리 실행한다. 타이머 판정 실패로 확인된 것은 아니다.
- 최신 main 병합 후 검증 결과는 PR 본문에 기록한다.
