# 대시보드 UI·성능 개선 (#43–#46)

## 변경

- #43: SSE 이벤트를 80ms 단위로 모으고, 진행 중 조회가 있으면 후속 조회로 합친다. CHAT은 메시지만 조회하고 TOOL_START/TOOL_END는 이벤트 로그만 갱신한다. 메시지 비공개 전환은 조회 전에 즉시 반영하며 세션·방송 변경 시 오래된 응답을 무시한다.
- #44: 실시간 관제 상단에 강퇴 결정 대기·최장 대기·확인된 강퇴 실행 실패를 표시한다. 클릭하면 요청 표로 초점을 이동하고 필터를 적용한다. 비정상·판정 대기 수치는 정상보다 앞에 표시한다. API 미연동 상태에서는 숫자 대신 대시와 연동 안내를 표시한다.
- #45: 기간 통계 설명을 줄이고 판정 정의는 펼침 도움말로 제공한다. 모바일 강퇴 요청 표는 시간·결정·실행을 우선 표시하고 나머지는 요청 상세에서 제공한다. 방송 목록도 추가 수치를 방송 상세에서 볼 수 있다. 실시간 방송별 표와 AI 내역 표도 핵심 열을 먼저 표시하고 채널·메시지 상세로 나머지를 제공한다.
- #46: 방송별 막대에 0·중간·최댓값 눈금과 검사 건수를 추가한다. 선 그래프와 막대에는 자동 눈금임을 명시한다. 기간에 따라 눈금이 바뀌며 고정 눈금 옵션은 추가하지 않았다. 표 보기·키보드 툴팁·방송 없는 날 선 끊김은 유지한다.

## 요청 수 비교

같은 테스트 fixture에서 채팅 이벤트 20개를 전송하고, 첫 메시지 조회가 시작된 후 20개를 추가 전송했다. 메시지 응답은 180ms 지연시켰다. 그 뒤 TOOL_START/TOOL_END 각 20개를 전송했다.

| 관측 | 변경 전 HEAD | 변경 후 |
| --- | ---: | ---: |
| 채팅 구간 메시지 조회 | 41 | 2 |
| 채팅 구간 검토 조회 | 82 | 0 |
| 채팅 구간 사건 조회 | 41 | 0 |
| 채팅 구간 세션 조회 | 42 | 2 |
| 채팅 구간 현재 방송 조회 | 1 | 0 |
| 도구 이벤트 구간 추가 API 요청 | 200 | 0 |

변경 전 실행은 더 오래 걸려 채팅 구간에 5초 주기 재조회도 포함됐다. 이벤트당 요청 수를 정확히 분리한 결과나 운영 환경의 처리량·지연 시간 측정은 아니다. 변경 후에도 세션 확인과 5초 주기 복구 조회는 유지한다. 연속 이벤트 테스트는 최신 메시지 표시와 메시지 조회 최대 2회, 검토·사건 재조회 0회 및 도구 이벤트 추가 조회 0회를 검사한다.

## 검증

- `VITE_USE_API=true npm run build`, `VITE_USE_API=false npm run build`: 각각 타입 검사·프로덕션 빌드 통과.
- `npm run test:chat`: 기존 56개 + 새 2개, 총 58개 통과.
- 화면 저장 옵션을 켠 전체 실행에서는 목업 초기 로그인 버튼 대기 타임아웃 1건이 있었다. 표준 전체 재실행은 58개 통과했고, 최종 UI 화면 저장은 새 관리자 UI 테스트만 분리 실행해 통과했다.
- 새 UI 테스트는 위험 요약 필터, 표로의 초점 이동, API 미연동 안내, 360·390px 가로 넘침, 모바일 상세, 키보드 툴팁, 눈금·검사 건수 표시를 확인한다.
- 화면 증거: `docs/evidence/dashboard-review/review-admin-*.png`.

## 범위

시스템 운영자 집계 API는 여전히 후속 연동 대상이다. 위험 요약의 실제 데이터도 API 연결 후 제공된다. 화면 지연 로딩·로그인 배경 영상 최적화는 이번 네 이슈 범위에 포함하지 않았다.
