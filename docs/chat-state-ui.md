# P0 위반 메시지 미노출 및 채팅 상태 처리

2026-10-22 현재 소스 기준. API 데이터 연결은 `VITE_USE_API=true`로 선택하는 `src/LiveConsole.vue`다. (#12 이후 `VITE_USE_LIVE_V1`은 쓰지 않는다.) 목업 시청자 데이터는 `src/ViewerPage.vue`가 연결하며, 두 화면의 시청자 UI는 `src/ViewerScreen.vue`를 공통으로 사용한다. 제한 안내와 시간 포맷은 `src/ChatTimeoutNotice.vue`와 `src/chatTime.ts`를 사용한다. 아래의 API 이력·SSE 복원 검증은 API 경로에 해당한다.

## 공통 시청자 화면

- Desktop: 왼쪽 영상·오른쪽 채팅, 영상 아래 방송 정보. 모바일: 영상·정보·채팅을 세로 배치한다.
- 검색은 현재 권한으로 받은 메시지의 원문·작성자명에만 적용한다. 채팅 접기·영화관 모드 전환 중에도 API/SSE 연결과 비공개 변경 처리는 유지한다.
- 사용자가 위로 스크롤한 경우에는 제한 시작·해제와 새 메시지 도착에도 위치를 유지하고 새 메시지 버튼으로 복귀한다. 최신 메시지를 따라가던 경우에는 입력부 높이가 바뀌어도 계속 최신 메시지를 표시한다.
- 입력창은 두 모드에서 같은 이름·전송 버튼·500자 제한을 사용한다. TIMEOUT 중에는 입력부만 제한 안내창으로 교체하고, 채팅 목록·검색·스크롤·실시간 수신은 유지한다. 강퇴·방송 종료·초기 상태 확인 중에는 입력과 전송을 비활성화한다.
- API의 조회·전송·재접속·현재 방송 및 계정 변경 감지·제재 복원은 `LiveConsole.vue`에 유지한다. 화면 컴포넌트는 메시지·상태·초안을 받고 사용자 동작을 돌려준다.
- API에는 서버가 제공한 방송 시작 시각과 실제 연결 상태를 표시한다. 목업 방송명·구독자 수·시청자 수·반응 수와 시연 버튼은 목업에 한정한다.
- 시청자 UI만 공통화하며 운영자·시스템 운영자의 역할 화면과 검토·제재 API 계약은 유지한다.

## 채팅 입력부만 가리는 제한 안내창

- TIMEOUT이 적용되면 채팅 입력부만 제한 안내창으로 교체한다. 채팅 제목·목록·접기 버튼은 그대로 표시하며 다른 사람의 공개 채팅을 계속 읽을 수 있다. 제한 사유, 한국 시간 기준 종료 날짜·시각, 남은 시간과 영상 시청 가능 안내를 제공한다.
- 이 창은 목록 아래 입력부 자리에 표시되며 모바일에서도 읽을 채팅 공간을 남긴다. 영상·검색·로그아웃·새로고침·채팅 접기를 계속 이용할 수 있다. 채팅을 접어 둔 상태에서 제한이 시작되면 채팅을 열어 안내한다.
- 기한 만료 또는 서버의 해제 상태가 확인되면 안내 대신 입력창과 초록색 해제 안내가 나타난다. 채팅 목록은 제한 중과 해제 후 모두 유지한다. 창에 키보드 초점이 있었다면 입력창으로 돌려준다.
- 창이 나타나면 안내 영역으로 초점을 옮기지만 영상 쪽의 키보드 이동을 가두지 않는다. 창이 사라졌거나 계정·방송이 바뀐 뒤에는 이전 비동기 초점 이동을 적용하지 않는다.
- 제한 중에도 새 공개 채팅을 즉시 표시한다. 메시지가 숨겨지거나 복원된 SSE 결과도 계속 반영하고, 다른 시청자의 비공개 원문은 제거한다.
- 종료 시각이 없는 TIMED_OUT에도 확인 중 문구가 있는 제한창을 표시한다. 강퇴·방송 종료는 TIMEOUT 창보다 우선하며, 이때 제한 해제로 잘못 알리지 않는다.

## 목업·API 공통 시간 표시와 효과

- 제한 종료 날짜·시각에 연·월·일과 초까지 표시하고 한국 시간을 명시한다. 브라우저의 시간대 설정과 관계없이 `Asia/Seoul`로 표시한다.
- 남은 시간은 `23시간 46분 54초` 또는 `9분 59초`처럼 표시한다. 종료 시각을 모르는 API 응답은 확인 중 안내를 유지한다.
- 두 모드 모두 제한 시작 시 주황색 안내를 짧게 강조한다. 제한 시간이 지나거나 서버가 제한을 해제하면 초록색 해제 안내를 5초간 표시하고 입력창을 강조한다. 목업에서는 시연 버튼으로도 해제할 수 있다.
- 계정 전환이나 강퇴로 제한 안내가 사라질 때는 해제 효과를 표시하지 않는다. 컴포넌트가 사라지면 효과 타이머를 정리한다.
- 모션 줄이기 설정에서는 애니메이션을 끄고 안내와 상태 변화는 그대로 표시한다. 매초 바뀌는 남은 시간은 실시간 음성 알림에서 제외한다.

목업 시청자로 로그인한 뒤 영상 아래 **목업 시연**에서 **제한·해제 효과 보기**(10초 후 해제), **24시간 표시 보기**, **제한 해제 시연**을 사용할 수 있다. UI 시연은 로컬 목업 제한 상태만 바꾸며 API를 호출하거나 위반 사건을 생성하지 않는다. 시연용 10초는 정책에 정의된 제재 시간이 아니다. 이 변경은 기존 목업의 전체 정책 판정 로직을 v3.1로 교체하는 작업을 포함하지 않는다.

## 목업 직접 입력 금지어

`src/stores/liveGuard.ts`의 목업 채팅 전송에서 `시발` 한 단어만 검사한다. NFKC 정규화 후 부분 일치하며, 정책의 예외 단어 `시발점`·`시발역`을 제외한다. 다른 욕설과 띄어쓴 우회 표현은 감지하지 않는다. 한 메시지 안의 여러 일치는 위반 한 건이다.

- 첫 욕설 사건: HIDDEN과 작성자 사유 표시, 입력 유지.
- 두 번째 욕설 사건: HIDDEN과 600초(10분) TIMEOUT.
- 세 번째 이상: HIDDEN과 86400초(24시간) TIMEOUT. 강퇴 승인 없이 채팅 제한을 적용하며 시청은 유지한다.
- 이력은 현재 목업 방송 데이터에서 같은 작성자 ID의 확정 PROFANITY 사건만 센다. 다른 유형·다른 시청자·취소된 사건은 제외하고, 강퇴 검토에 소진되거나 시간이 지난 사건은 욕설 누적에서 빼지 않는다.
- 최근 24시간의 재사용되지 않은 확정 사건이 3건 모이면 강퇴 검토를 별도로 만들되 자동 강퇴하지 않는다. 기존 대기·결정된 검토의 사건은 재사용하지 않는다.

직접 입력한 욕설은 목업 사건·이력에도 남고, 숨긴 원문은 목업 작성자와 운영자만 볼 수 있다. 정책 조회·Agent 호출을 모의로 기록하지 않는다. 기존 **빠른 시연**의 다른 유형 판정 로직은 이전 버전 그대로다. API 모드에는 이 금지어 규칙을 적용하지 않는다. **제한 해제 시연**은 입력 제한만 없애고 사건 이력을 남기므로 다음 위반 단계를 바로 확인할 수 있다. 새로고침하면 초기 fixture로 돌아간다.

## 화면 동작

| 상태 | 동작 |
| --- | --- |
| PUBLIC | 일반 채팅 표시 |
| HELD | 작성자·담당 운영자에게 임시 비노출과 검토 중 표시 |
| HIDDEN | 작성자·담당 운영자에게 숨김 상태 표시 |
| 작성자 사유 | 규칙으로 바로 숨긴 욕설·링크(`PROFANITY_INCLUDED`·`LINK_NOT_ALLOWED`)는 사유 코드의 정책 문구, 그 밖에는 서버 `moderationNotice` → `moderationReasonCode` 라벨 → HELD 일반 안내 순서로 표시. 임의의 위반 사유를 만들지 않음. 채팅 제한 종료 시각은 메시지마다 붙이지 않고 입력부 제한 안내에서만 표시(#14) |
| TIMEOUT | 입력부만 제한 안내창으로 교체. 다른 사람의 공개 채팅·실시간 수신·검색·스크롤 유지. 한국 시간 기준 종료 날짜·시각과 남은 시간(시간·분·초), 제공된 사유 표시, 영상 시청 유지 |
| KICKED / LIVE_ACCESS_BLOCKED | 영상 대신 방송 종료까지의 제한 안내, 기존 채팅·입력 초안 제거, 입력 차단, SSE 종료 |
| LIVE_ENDED | 방송 종료 안내, 플레이어 제거, 입력 차단, SSE 종료 |

다른 시청자의 HELD·HIDDEN은 목록에서 제외한다. 이미 공개된 메시지를 비공개로 바꾸는 이벤트를 받으면 재조회 완료 전에 원문을 즉시 제거한다. 공개 복구는 서버 재조회 결과를 따른다.

초기 이력 조회가 성공하기 전에는 플레이어와 입력을 활성화하지 않는다. SSE 재연결 시 재조회하고, 5초 간격 및 창 포커스 복귀 시 현재 방송·이력·제한을 다시 확인한다. 강퇴·종료·계정 또는 방송 전환 이전에 시작된 오래된 조회 결과가 새 상태를 덮어쓰지 않도록 요청 세대를 확인한다.

## Backend 응답 추가

같이 수정한 Backend는 `GET /api/lives/{liveId}/messages`의 `data.timeoutUntil`에 **현재 요청자**의 활성 제한 종료 시각 또는 `null`을 반환한다. 페이지에 본인 메시지가 없어도 제한이 복원된다. 다른 사람의 제한 종료 시각은 반환하지 않는다. 기존 채널 경로는 `null`을 반환할 수 있다.

```json
{
  "data": {
    "items": [],
    "nextCursor": null,
    "timeoutUntil": "2026-10-22T05:30:00Z"
  },
  "traceId": "example"
}
```

Backend의 `contracts/openapi.yaml`, `MessagePage` DTO, `LiveService.history`를 함께 변경했다. DB 마이그레이션은 추가하지 않았다. 구버전 Backend에서는 본인 메시지의 `timeoutUntil`을 대체 정보로 읽지만, 본인 메시지가 페이지 밖이면 제한 복원을 보장할 수 없으므로 Backend 변경도 함께 반영해야 한다.

현재 liveId 통합 Backend 경로는 기존 구현의 `LIVEGUARD_POLICY_VERSION=v3.1` 및 `LIVEGUARD_TBD_FIXTURE_ENABLED=true` 조건을 따른다. 이 시험 설정은 운영 정책의 확정을 의미하지 않는다.

## 검증

Frontend의 Mock·API 모드 빌드 및 Chromium 브라우저 테스트 26개 통과. API 테스트는 격리된 HTTP/SSE 서버를 사용하고 목업 테스트는 별도의 Vite 서버에서 실행한다.

1. 작성자 사유·검토 중 표시, 다른 시청자 원문 제외, 운영자 원문 표시
2. 잘못된 API 응답에 타인 비공개 메시지가 있어도 화면에서 제외
3. 비공개 변경 후 재조회가 실패해도 원문 즉시 제거, 서버 공개 복구 반영
4. 본인 메시지가 없는 목록에서도 TIMEOUT 복원, 새로고침 유지, 서버 취소 후 전송 가능
5. TIMED_OUT 응답으로 입력 차단, 종료 시각 후 입력 복구
6. KICKED 응답으로 플레이어·채팅 제거, 새로고침 후 제한 유지
7. 진행 중 이력 조회보다 강퇴 SSE 우선, 새 방송에 이전 제한을 넘기지 않음
8. LIVE_ENDED 후 플레이어 제거·입력 차단
9. 같은 방송에서 서버가 강퇴를 취소하면 제한 화면과 이전 안내 제거
10. 늦게 도착한 현재 방송 응답이 종료된 방송을 다시 활성화하지 않음
11. 다음 날까지 이어지는 24시간 제한의 종료 날짜와 남은 시간을 명시적으로 표시
12. 목업 10초 제한 시작 효과·입력부 교체·다른 사람의 새 채팅 수신·영상 유지, 만료 후 해제 효과·채팅 전송·효과 종료
13. 다른 시간대의 모바일 브라우저에서도 한국 시간으로 다음 날 종료 표시, 가로 넘침 없음, 모션 줄이기 적용
14. 목업 계정을 바꿔도 사용자별 제한 유지, 다른 사용자의 해제로 잘못 안내하지 않음, 수동 시연 해제
15. 직접 입력한 금지어의 메시지별 누적, 첫 숨김·두 번째 10분·만료 후 세 번째 24시간, 다른 시청자에게 원문 비노출
16. 다른 유형의 기존 사건과 다른 시청자의 사건을 욕설 누적에서 제외
17. API 모드에서는 같은 문구를 서버로 보내고 서버 응답의 공개·제재 상태를 따름
18. 같은 브라우저 크기에서 Mock·API 영상과 채팅의 가로 배치·폭·좌표 일치, 영화관 모드 전환, API에 가상 집계 미표시
19. 채팅 검색·접기 중에도 SSE 비공개 변경 시 원문 제거, 재공개 시 서버 응답으로 복원
20. 방송이 없으면 영상·입력 비활성화, 방송 시작 확인 뒤 활성화
21. API 모바일에서 읽을 채팅 목록을 유지하고 입력부만 제한 안내로 교체, 사유·종료 안내·영상 유지 및 가로 넘침 없음
22. 세션 만료 시 시청자 화면·초안·캐시 제거와 SSE 종료
23. 위로 스크롤하면 제한 중 새 메시지 도착과 제한 해제에도 위치 유지, 새 메시지 버튼으로 최신 메시지에 복귀
24. 접어 둔 채팅을 열어 입력부 제한 안내 표시, 제한 중에도 새 공개 채팅·검색·접기·SSE 비공개 변경을 즉시 반영
25. 종료 시각 없는 TIMED_OUT도 제한창과 확인 중 안내 표시
26. TIMEOUT 중 방송 종료 시 제한창 제거·영상 종료·입력 차단, 잘못된 해제 알림 없음

```bash
# frontend 디렉터리
npm ci
npx playwright install chromium
npm run test:chat
VITE_USE_API=true npm run build
```

## 실행 중인 Compose 반영

2026-10-22 종료 날짜·남은 시간 표시 개선은 로컬 Frontend 이미지를 재빌드해 `localhost:3000`에 반영했다. 실제 Backend의 다음 날까지 이어지는 TIMEOUT을 조회하여 종료 날짜·시간 단위 표시, 입력 차단, 영상 시청 유지를 확인했다. 채팅 전송이나 제재 변경 없이 조회로 검증했다.

같은 날 시간 표시 공통화와 목업 효과도 Frontend 이미지만 재빌드해 반영했다. 실행 중인 `localhost:5173` 목업에서 실제 10초 경과 후 해제 안내와 입력 복구를 확인했고, `localhost:3000` API 화면에서는 기존 제한의 다음 날 종료 날짜·시간 표시와 입력 차단을 확인했다. API 화면에는 목업 시연 버튼을 노출하지 않는다. Backend와 DB 컨테이너는 재생성하지 않았다.

시청자 UI 공통화도 같은 방식으로 Frontend만 재빌드해 반영했다. 실제 두 URL을 1440×1000 브라우저에서 열어 영상 좌표·너비 `(24, 80, 966)`와 채팅 좌표·너비 `(1014, 80, 402)`가 일치함을 확인했다. 목업 욕설 제한과 실제 서버의 기존 TIMEOUT 모두 입력 비활성화·동영상 유지가 동작하고, 실제 운영자 계정은 기존 Studio 콘솔을 사용한다. 실제 API 검증 중에는 채팅 전송이나 제재 변경을 하지 않았다.

이후 채팅 전체를 가리던 동작을 입력부만 가리는 방식으로 수정했다. 현재 동작은 위의 공통 화면·제한 안내 절을 따른다. 채팅 목록과 입력부를 별도로 렌더링하여 제한 중에도 공개 채팅 수신·검색·스크롤을 유지한다. Frontend만 재빌드한 뒤 실제 5173·3000에서 목록 표시·입력부 교체·검색 활성화·영상 재생을 확인했다. 목업은 제한 중 새 채팅 수신과 실제 10초 후 입력 복구, API는 새로고침 후 같은 제한 화면 복원을 확인했다. API 채팅 전송·제재 변경 없이 로그인과 조회만 수행했으며 Backend·DB·Agent 컨테이너는 재생성하지 않았다. 브라우저 테스트 26개와 Mock·API 타입 검사·빌드를 통과했다.

이후 소스 수정은 실행 중인 컨테이너에 자동 반영되지 않는다. Infra `.env`의 빌드 경로가 수정한 소스를 가리키는지 확인한다. 이번 시간 표시 공통화와 목업 효과 변경은 Frontend만 반영한다.

```bash
# infra 디렉터리
docker compose up -d --build --no-deps frontend
```

이전 작업에 포함된 목록 밖 TIMEOUT 복원은 위의 Backend 응답 필드에 의존한다. 구버전 Backend를 유지하는 환경에서는 그 기능을 온전히 사용할 수 없으며, Backend 변경은 담당자와 별도로 조율한다.
