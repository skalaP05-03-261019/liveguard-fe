# 발표 참석자 시청자 접속

`http://<발표 PC Wi-Fi 주소>:3000/?entry=viewer` 링크로 시청자 로그인 창을 바로 엽니다. 링크는 로그인 진입만 선택하며 권한은 서버 계정의 VIEWER 역할로 결정됩니다. 비밀번호를 URL에 넣거나 자동으로 권한을 부여하지 않습니다.

시연 앱은 서버에 연결하지 못할 때 `SKALA 4층 Wi-Fi`에 연결한 후 다시 접속하라는 안내와 재시도 버튼을 표시합니다. 행사 장소가 바뀌면 프론트엔드 빌드 환경의 `VITE_DEMO_WIFI_NAME`을 실제 SSID로 설정합니다. 연결 실패가 Wi-Fi 때문이라고 단정하지 않으며, 연결 후에도 문제가 계속되면 진행자에게 문의하도록 안내합니다.

로컬 시연 DB에 준비된 `seed-demo-participants.sql`을 적용하면 참가 계정 `p001`~`p200`을 사용할 수 있습니다. 참가자별로 서로 다른 순번을 배정합니다. 로컬 시드 비밀번호는 `liveguard-local`입니다. 발표용 로컬 DB 외에는 이 스크립트를 실행하지 않습니다.

Compose frontend는 기본 127.0.0.1에만 바인딩되므로 발표 PC 로컬 `.env`에 `FRONTEND_BIND=0.0.0.0`을 설정하고 frontend를 다시 생성해야 합니다. 같은 Wi-Fi의 다른 기기에서 접속할 수 있으며, Wi-Fi가 기기 간 접속을 차단하면 접속되지 않을 수 있습니다. 발표 PC가 켜져 있고 Docker가 실행 중이어야 하며 Wi-Fi 변경 시 주소도 다시 확인합니다. 외부 인터넷 접속을 제공하는 설정은 아니며 외부에는 별도의 HTTPS 배포/연결이 필요합니다.

검증: FE 프로덕션 빌드, 3000번 frontend 재빌드, 로컬 시연 계정 200개 및 채널 VIEWER 멤버십 생성. 발표 PC의 Wi-Fi IP 주소로 실제 Chromium 로그인(p001)을 수행하여 시청자 화면 진입과 운영자/관리자 화면 미노출을 확인했습니다. 별도 참석자 기기에서의 접속 검증은 아직 하지 않았습니다.
