# 정책·API 정합성 보완과 로컬 성능/보안 평가 (#48–#52)

## 변경 이유와 범위

정책 v3.2와 OpenAPI/ERD 대조에서 찾은 표시·이벤트·목업 집계 문제를 수정했다. 실제 제재 임계치·권한·저장 구조·API 요청 스키마는 변경하지 않는다. 기준 문서는 BE `1b1df68f9661f6fc4d17bacd6295c91724dc03c9`의 `docs/policy/POLICY.md`, `contracts/openapi.yaml`, `docs/erd.md`다.

### #48: 기준 사건 수와 결정 상태

- 사건 수는 유형 배열 길이가 아닌 고유 `basisCaseIds` 수다. 한 사건에 유형이 둘이어도 한 건이다. 데스크톱과 모바일 상세 모두 같은 계산을 사용한다.
- 결정 상태 매핑은 `reportSummary.ts`에서 분리한다. PENDING만 대기이며 DECIDED의 APPROVE/REJECT만 승인/기각이다. 결정 누락·모순·알 수 없는 상태는 '결정 정보 미확인'이다.
- 실제 BE에서 쓰던 INVALIDATED는 '무효 · 계약 확인 필요'로 별도 표시하고 승인·기각·대기 분포와 승인율에서 제외한다. OpenAPI의 새 enum으로 선언하거나 요청으로 보내지 않는다. BE의 공식 계약 정리는 #88/#89 선행 사항이다.
- '스트리머 승인/결정'이라는 추정은 없애고 '승인/기각/검토 결정'으로 표시한다. 계정 역할과 채널 역할을 합치지 않는다.

### #49: SSE 버전과 REST 경합

- 메시지, 사건, 검토, 조치의 ID별 버전을 구분한다. 서로 다른 엔티티 버전을 비교하지 않는다.
- 버전이 제공된 이벤트는 오래된 것만 무시한다. 같은 버전의 연관 상태 알림은 처리하고 eventId 중복 방지는 유지한다.
- 버전 없는 진행/생명주기 이벤트에 임의 버전을 붙이지 않는다. 도구 진행은 사건 버전 때문에 버리지 않는다.
- REST에서 받은 메시지 버전도 기준에 반영하고, 최신 이벤트보다 오래된 메시지 응답으로 화면을 되돌리지 않는다. 서버의 재조회·현재 상태가 최종 근거이며 SSE 전체 이력 재생을 가정하지 않는다.
- 유효한 비공개 전환은 HTTP 조회 전에 적용한다. 사용자·방송 전환에서는 버전 상태를 초기화한다.

### #50: 기간 목업의 모집단

기존 목업은 기간에 걸치는 방송 전체 수치를 시작일에 넣었다. 이제 타임스탬프가 있는 합성 채팅 그룹과 검토 요청으로 목업을 만들고, 메시지 `sentAt`·요청 `createdAt`이 `[from,to)` 안에 있는 건만 집계한다. 그룹의 count는 같은 시각에 보낸 합성 메시지 수이며 실제 방송 전체 수치를 비례 배분하는 로직이 아니다.

일별 합계는 메시지를 보낸 한국 날짜 기준이다. `end=from`인 방송과 `start=to`인 방송은 제외한다. 자정을 넘는 방송도 요약 합계와 daily 합계의 모집단이 같다. 채팅 없는 날은 '방송 없음'으로 단정하지 않는다.

이는 **BE #89 초안 의미에 맞춘 목업**이다. 실제 관리자 API나 확정 계약을 새로 만들지 않았다. API 경로·권한·가시성 스냅샷 정의의 최종 합의는 BE #88/#89에서 해야 한다.

## 실제 로컬 평가 (#51/#52)

재현 명령:

```bash
node scripts/evaluate-local.mjs --local-fixture --sessions=100 --rate=100 --seconds=10
```

로컬 Docker Compose의 DB와 Spring API를 사용한다. 스크립트는 전용 합성 사용자/채널을 생성하고 기존 시연 데이터는 수정하지 않는다. 비밀번호 해시는 기존 로컬 viewer에서 DB 내부 복사하며 쿠키·비밀번호·토큰 값은 보고서에 기록하지 않는다. 시험 방송은 마지막에 종료하고 재현용 합성 행은 남긴다. `--local-fixture`와 loopback 주소만 허용한다. 비밀번호가 기본 로컬 값과 다르면 `LIVEGUARD_TEST_PASSWORD` 환경변수로 전달한다.

### 100개 세션 결과

보고서: [c24f4d4453eb.json](evidence/local-evaluation/c24f4d4453eb.json)

| 항목 | 관측 결과 |
| --- | ---: |
| 독립 로그인 세션 / SSE 수신자 | 100 / 100 |
| 순간 100개 채팅의 POST 완료 | 약 526ms |
| 지속 부하 | 10초간 1,000개, 약 100개/초 |
| 공개 채팅 저장·수신 | 1,100개 저장, 각 수신자가 모두 수신 |
| 중복 CHAT 이벤트 | 0 |
| POST 지연 p50 / p95 / p99 | 210 / 420 / 479ms |
| SSE 전달 지연 p50 / p95 / p99 | 216 / 421 / 484ms |
| 대표 브라우저 프레임 간격 p95 | 약 16.7ms |
| 관측 long task | 0 |
| 검색 입력+해제 드라이버 작업 | 약 122ms, 1회 샘플 |
| 로컬 보안·생명주기 검사 | 26개 통과 |

100개 수신자는 Node의 독립 인증 HTTP/SSE 클라이언트이고, 실제 UI는 Chromium 1개에서 검증했다. 100개 브라우저 동시 렌더링 결과가 아니다. SSE 지연은 POST 시작부터 각 수신자가 CHAT을 파싱할 때까지이며 110,000개 수신 샘플이다. 프레임과 메모리는 짧은 headless 관측값이므로 사용자 환경 전체의 성능이나 장기 누수 없음의 증거로 쓰지 않는다. `performance.memory` 값도 해상도가 낮고 GC를 강제하지 않았다.

평가 부하는 PUBLIC/PASS 경로이며 각 응답이 PUBLIC인지 검사하고 해당 메시지들이 guard 사건을 생성하지 않았는지 DB로 확인한다. 별도로 부하 중 보낸 HIDDEN 메시지는 작성자만 받고 나머지 99명은 받지 않는 것을 확인했다. 실제 LLM 지연·비용·장기 메모리·킥 승인 재검증 부하·운영 SLO는 미검증으로 보고서에 명시했다. 따라서 #51/#52 전체 완료나 운영 성능 보장으로 선언하지 않는다.

### 로컬 보안과 방송 생명주기

세션/CSRF, 타 채널 REST·SSE·전송 거부, 시청자/STREAMER 멤버의 관제 접근 거부, 미소속 PLATFORM_ADMIN 원문 접근 거부, HIDDEN의 작성자·담당 MODERATOR 전용 전달, clientMessageId 멱등성, 부하 중 원문 비노출, TIMEOUT 전송 거부, 로그아웃 후 SSE 종료·이전 세션 재사용 거부, 중복 방송 시작, 종료 후 전송 거부, 새 liveId의 이력/제한 분리를 확인했다. 로컬 HTTP 쿠키 속성은 관측만 기록하며 운영 HTTPS 배포 설정을 통과 처리하지 않는다.

### 첫 100명 실험의 잘못된 모집단

[4f6cb8ca75d3.json](evidence/local-evaluation/4f6cb8ca75d3.json)은 실패 기록으로 보존했다. 채팅 본문의 무작위 UUID가 PII 후보 27건을 만들어 비공개로 처리됐는데, 모든 수신자가 전부 받는다는 잘못된 기대를 걸어 타임아웃이 발생했다. 이는 SSE 유실 입증이 아니다. 숫자 없는 고유 합성 문장으로 바꾸고 각 POST의 PUBLIC을 검사한 뒤 재측정했다. 개인정보 후보 경로의 Agent 실행·비용은 이 첫 실패 기록에서 분리 측정하지 못했으며 PASS 부하 결과와 합치지 않는다.
